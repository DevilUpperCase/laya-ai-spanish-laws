# Legal review by the lawyer or designated staff

The reviewer is the application user: a lawyer, or a designated employee working under the lawyer's responsibility. Record the actual person's name/role and dated review evidence. Being able to sign in does not automatically certify legal expertise or approve a release. No professional judgments or signatures have been generated by this project.

## Review search quality

`evaluation/review-queue.json` has 200 starting drafts across Spanish, Catalan, Galician and Basque and state/regional/provincial/municipal/island-foral levels. Repeated topics are starting prompts, not a completed independent test set. Rewrite them into realistic, distinct public-law questions with exact territories, references, dates and negative expectations. Include homonymous municipalities, historical/unknown-effectiveness cases and all required languages. Use public examples; do not put client facts into shared evaluation files.

Each case needs its own ID, query, language, tier, calibration/holdout split, temporal/negative flags and expected relevance judgments. Search the app, inspect the full official texts and record `section_version_id` values from the API results. Grade relevant versions consistently from 0 (irrelevant) to 3 (directly relevant). A negative case has no positive judgments. Preserve the original official citation/date/provenance findings as separate reviewed evidence; ranking metrics do not verify those facts.

Set each case's actual `reviewer` and `review_evidence_sha256` to the hash of its dated review artifact. A hash alone does not prove review; keep the actual artifact under protected independent custody. Both calibration and holdout must remain disjoint. The holdout must cover all four languages, all five tiers, temporal and negative cases, with positive cases in every language/tier stratum.

During calibration, use public measurements from `python -m evaluation.pilot` and the calibration judgments to agree numeric Recall@20, MRR@10, nDCG@10, Precision@5, negative false-positive and performance limits. Freeze and independently record the policy hash **before** collecting/evaluating holdout rankings:

```powershell
.venv/Scripts/python.exe -m evaluation.freeze_policy --cases reviewed-cases.json --proposal policy-proposal.json --pilot verification/reports/hardware-pilot.json --review-evidence actual-acceptance.md --reviewer "Actual reviewer" --output frozen-policy.json
```

The proposal requires `minimums` for `recall20`, `mrr10`, `ndcg10`, `precision5`, `stratum_minimums` with the same four metrics for every language/tier, `maximum_negative_false_positive_rate` and `maximum_p95_ms`. The tool checks structures and hashes; it cannot prove identity, professional competence, an honest prior freeze or the production workload. Keep its receipt in independently timestamped/immutable custody.

Use `python -m evaluation.collect_rankings --cases reviewed-cases.json --policy frozen-policy.json --policy-sha256 INDEPENDENT_RECEIPT_HASH --output rankings.json --public-cases` to collect the actual public holdout results after the freeze. It requires a matching reviewed dataset/policy and refuses to turn HTTP failures into negative rankings. The observations file records latency and engine warnings.

Rankings JSON maps each holdout ID to unique section-version IDs in returned rank order; when multiple passages share a version, keep the first occurrence. Evaluate with `evaluation.evaluate` as described in [evaluation/README.md](../evaluation/README.md). Assess actual performance/load, provenance, date and territorial accuracy separately. Passing metrics does not activate LAYA reranking: that requires a distinct reviewed comparison with the baseline and an adoption decision.

## Review nationwide coverage

Use a copy of `sources/nationwide-review-queue.csv`; export commands overwrite the generated starting queue, so preserve human edits in a separate artifact. Every required jurisdiction must have a complete set of official normative sources and audited current/available-history ranges. Regional BOE republications cannot substitute for missing local ordinances.

For each source, fill `sources/source-audit.template.json`: source capability/pagination, actual dates, reuse approval, expected/integrated publication counts, missing periods, original fixtures and reconciliation evidence hashes. Explain officially unavailable history with reviewed evidence; do not simply label a missing archive unknown. Check annexes, language variants, island/foral institutions and geographic identities. Required missing periods block release.

For a jurisdiction audit row, supply the reviewed source-audit path/hash, actual reviewer/date and verified status only when all applicable obligations are proven. `scripts/verify_coverage_queue.py --queue <reviewed-copy.csv>` checks exact inventory equality and audit structures. It does not modify database coverage flags or confer legal approval. Institutional inventory review still must resolve the INE island date issue and the foral supplement.

## Review release and licenses

The final reviewer/owner assembles substantive evidence for the acceptance matrix G01–G22. Keep security/tenant-isolation, model pins, source coverage, quality, performance, deletion/restore/expiry, licensing and deployment evidence distinct. Review actual package/model/container/source licenses from `verification/reports/license-inventory.json`; metadata is not clearance. `verify_package.py --release` checks the evidence package and remains blocked until the complete contract is met.

For local development, users may continue testing the app while these reviews are open. The interface must continue to disclose incomplete coverage, unknown effectiveness and degraded search engines. It must not claim that a lawyer's unrecorded use constitutes nationwide first-release acceptance.
